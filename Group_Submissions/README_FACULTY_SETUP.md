# Faculty Setup Checklist

Before sharing the repository:
- [ ] Create the master repository under the faculty GitHub account.
- [ ] Choose visibility and confirm institutional policy.
- [ ] Upload approved problem statement PDFs.
- [ ] Confirm group allocation and naming convention.
- [ ] Confirm default branch (normally `main`).
- [ ] Confirm fork policy and whether public forks are permitted.
- [ ] Test that a group leader can invite the other three students as collaborators.
- [ ] Decide Pull Request deadline and review/merge policy.
- [ ] Share the master repository URL with students.

## Workflow notes
1. A normal fork is owned by the group leader. The leader invites the other group members as collaborators if write access is needed.
2. Students must not share GitHub passwords.
3. Organisation fork policies and permissions may affect this workflow.
4. Students should commit using their own authenticated accounts for attributable contribution history.
5. Public repositories and forks are visible to everyone. Never upload secrets or confidential information.
6. Review Pull Request diffs before merging; each PR should add only the submitting group's folder.
7. Keep groups' folders separate to reduce merge conflicts.
8. Do not ask students to merge their own Pull Requests; faculty reviews and merges.
